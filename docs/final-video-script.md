# NEXUS Prime 展示讲稿

建议时长：6 分钟  
展示方式：浏览器页面 + 终端命令

## 0:00 - 0:30 开场

大家好，我是庄颂，学号 20241334。本次展示的是 NEXUS Prime 制造业仓配经营管理信息系统。

系统采用前后端分离架构：前端是 Angular 21 SPA，后端是 Flask REST API，数据库本地为 SQLite，生产目标为 Supabase PostgreSQL。系统围绕库存、采购、销售、应收、盘点、报表、文件、通知、经营分析和权限审计构建完整业务闭环。

## 0:30 - 1:00 项目结构

展示项目目录。

`backend/` 是后端 API，包含模型、服务、接口、迁移和测试。  
`frontend/` 是前端 SPA，包含核心服务、应用外壳和业务页面。  
`docs/` 是报告、部署说明和截图。  
`scripts/` 是启动、清理、预检和部署脚本。  
`legacy/monolith-flask/` 是旧版 Flask/Jinja2 单体快照，用来对照说明从 Railway 单体页面升级到前后端分离架构；它不参与新版运行、构建和部署。首页、登录和注册的样式独立维护，避免被业务页面样式覆盖。

## 1:00 - 1:40 首页与登录

打开入场页，说明系统先进入一个独立首页。首页使用制造现场、仓储通道和车间图作为真实业务背景，再点击进入登录页。

登录页支持管理员和普通成员身份区分。本地演示管理员账号是：

```text
admin@nexus.com / admin123
```

本地演示普通账号是：

```text
user00001@nexus.com / password123
```

远程演示库使用部署时写入的自定义密码，不使用这两个本地默认密码。

注册流程在同一认证页内切换为单卡流程，包含姓名、用户名、岗位、邮箱、密码、验证码识别、服务许可、隐私说明、数据范围和三项许可确认。这些注意事项来自后端 `/auth/register-policy`，可以展开阅读后再提交。普通注册账号默认进入普通成员权限，管理员可后续调整角色和部门。

## 1:40 - 2:30 运营概览

进入 `/app/overview`。

顶部是命令栏，包含全局搜索、快捷动作、AI 分析入口、通知、主题切换和用户入口。底部是悬浮 Dock，核心页面按运营、仓配、供应、履约、财务、分析、协作、安全和个人分组。点击更多入口可以访问所有扩展页面。

运营概览展示关键指标、风险队列、仓配流向、任务状态、经营趋势和多张交互图表。页面可滚动，布局不会被 Dock 遮挡。

## 2:30 - 3:20 业务流程

依次展示：

物料与成品中心：查看 SKU、库存水位、供应商和低库存对象。  
补货建议：根据低库存生成建议，并可进入采购流程。  
采购补货中心：提交、审批、收货。  
销售履约中心：推进订单阶段。  
应收风控中心：处理账龄、催款和收款。  
盘点中心：创建盘点、录入数量并完成差异处理。

说明所有列表都有分页、搜索和详情页入口，关键动作会写入数据库和审计日志。

## 3:20 - 4:10 报表、文件与通知

打开报表工作室。展示报表模板、生成队列、归档记录和图表预览。

打开文件中心。展示文件列表、文件详情页和下载动作。文件详情包含基础信息、关联对象、文件说明和操作区。

打开通知中心。展示库存预警、审批提醒、催款提醒、报表完成提醒和系统消息。通知支持搜索、分页、跳转和标记处理。

## 4:10 - 4:50 AI 经营分析

打开 `/app/ai`。

页面包含经营摘要、分析会话、诊断面板、API 设置和多张业务图表。设置区可填写外部服务 Base URL、模型和 API Key，也可以使用本地分析模式。诊断区会显示当前服务状态、配置状态和业务数据快照。

经营分析不是单纯聊天窗口，而是从库存、采购、销售、应收、报表和通知数据中提取结构化结果。

## 4:50 - 5:20 设置、个人与权限

打开全局设置页。说明这里可以控制主题、密度、默认工作区、图表动效、Dock 标签和上下文面板。设置页还提供 Vercel、Supabase、Cloudinary、DeepSeek 的密钥获取入口和可复制部署命令，但真实密钥只写入后端或部署脚本环境变量，不进入前端。

打开个人工作台。展示头像、资料、岗位、偏好、个人任务和最近活动。

打开系统安全与审计日志。说明管理员与普通用户权限不同，登录、审批、收款、上传、报表生成和批量动作都会进入审计链路。

## 5:20 - 5:50 测试与部署

展示本地验证命令：

```powershell
cd backend
..\venv\Scripts\python.exe -m pytest -q
```

```powershell
cd frontend
npm test -- --watch=false
npm run build
```

部署准备已经完成：

前端使用 `frontend/vercel.json` 部署到 Vercel。  
后端使用 `backend/server.py` 与 `backend/vercel.json` 部署到 Vercel。  
数据库使用 Supabase PostgreSQL。  
`scripts/deploy-supabase-vercel.ps1` 可以完成预检、迁移、数据同步、前后端发布和健康检查。`scripts/preflight.ps1` 会确认 `legacy/monolith-flask/` 对照快照存在，同时排除它对旧平台引用的扫描，避免误删旧版证据。

## 5:50 - 6:00 总结

NEXUS Prime 已完成从旧单体页面到前后端分离管理信息系统的整理。系统具备清晰目录、统一 API、真实业务数据、分页搜索、详情页、图表、文件下载、AI 设置、权限审计、主题偏好和云端部署脚本。
